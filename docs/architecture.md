# Architecture

LaTeX Squiggly runs on three platforms, and all three must give the same answer
to the same typing. This document explains how that is arranged: what is the
source of truth, what is generated from it, and how the ports are held to it.

## One engine, three platforms

```
                    Sources/LaTeXUnicode           the engine: tables, tokenizer,
                    Sources/InputTracking          converter, trigger rules
                              │
                  swift build, then generators in scripts/
          ┌───────────────────┼─────────────────────┬──────────────────┐
          ▼                   ▼                     ▼                  ▼
  C# tables (*.g.cs)   JS tables (tables.js)   conformance/        site/assets/data.js
  windows/...Core      chrome/engine           reference.json      the website's demo
          │                   │                     │
          └──── each port is checked against ───────┘
                the reference, fragment by fragment
```

**The Swift engine is the source of truth.** It holds the symbol tables, the
tokenizer, the converter and the rules for when typing becomes a conversion. It
uses no system APIs, so it is fully testable, and the macOS app is a thin
shell around it.

**The other platforms are ports, not rewrites of the tables.** The Windows
(C#) and Chrome (JavaScript) engines are hand-written ports of the converter
logic, but their tables are generated from the Swift engine's own runtime
tables (`latex-squiggly --dump-tables`), never typed. A table transcribed by
hand drifts the first time somebody adds a symbol to one side.

**Agreement is checked, not assumed.** `scripts/generate-conformance-reference.py`
asks the Swift engine about 2,030 fragments: every symbol, every script
character, every refusal message, every case that must stay silent, and the
shapes that have caused bugs before. It records the answers in
`conformance/reference.json`. Each port replays every fragment and must give
the identical answer, down to how many characters to delete:

| Port | Runner | Checks |
|---|---|---|
| Windows | `windows/LaTeXSquiggly.Conformance` | 4,090 |
| Chrome | `chrome/test/conformance.mjs` | 4,076 |

Only the parts that touch the operating system are genuinely different per
platform, and each platform's README says which and why.

## What each platform adds

| Platform | Code | Catches typing with | Replaces text by | Docs |
|---|---|---|---|---|
| macOS | `Sources/LaTeXSquigglyApp` | a `CGEventTap` | posting synthetic key events | [macos.md](macos.md) |
| Windows | `windows/LaTeXSquiggly.App` | a low-level keyboard hook on its own thread | `SendInput` | [windows/README.md](../windows/README.md) |
| Chrome | `chrome/content` | page `beforeinput` and `keydown` events | `execCommand("insertText")`, after confirming the text in front of the caret | [chrome/README.md](../chrome/README.md) |

Two design points recur on every platform:

- **Stay quiet where LaTeX is source.** TeX editors, code editors, terminals
  and LaTeX websites such as Overleaf are excluded by default. A missed
  conversion costs a keystroke; a wrong one costs a document.
- **Keep as little as possible.** The last 64 typed characters, in memory,
  cleared on every click, arrow key and focus change. Nothing is written to
  disk except settings, and no platform makes a network request.

## Generated files

Generated files are committed, so building never requires the generators, and
their output is reviewable in a diff. They must never be edited by hand:
`scripts/check-all.sh` regenerates all of them and fails if anything differs.

| File | Generated by | From |
|---|---|---|
| `Sources/LaTeXUnicode/SymbolTableData.swift`, `ScriptTables.swift` | `scripts/generate-swift-tables.py` | Unicode character names in the script |
| `Sources/LaTeXUnicodeChecks/GeneratedCodepointChecks.swift` | `scripts/generate-swift-tables.py` | the same |
| `windows/LaTeXSquiggly.Core/Engine/*.g.cs` | `scripts/generate-csharp-tables.py` | the built Swift engine |
| `chrome/engine/tables.js` | `scripts/generate-js-tables.py` | the built Swift engine |
| `conformance/reference.json` | `scripts/generate-conformance-reference.py` | the built Swift engine |
| `conformance/windows-result.json` | the Windows conformance runner | a passing run |
| `site/assets/data.js`, marked regions of `site/index.html` | `scripts/make-site.py` | the Swift engine and the Windows result |
| `Sources/LaTeXSquigglyApp/MenuBarIconData.swift`, `assets/*.icns`, `assets/dmg-background.tiff` | `scripts/make-mac-icons.sh` | `assets/*.png` |
| `windows/LaTeXSquiggly.App/Assets/*.ico` | `scripts/make-windows-icons.py` | `assets/*.png` |
| `chrome/icons/*.png` | `scripts/make-chrome-icons.py` | `assets/menu-icon.png` |
| `site/assets/*.png` | `scripts/make-site-images.swift` | `assets/*.png` |

The image generators are not part of the drift check, because they need macOS
tools or Pillow and their output only changes when the artwork does. Run them
after changing anything in `assets/`.

## The website

`site/` is a plain static site with no build step, served by GitHub Pages
through `.github/workflows/pages.yml`. Its live demo uses the converter's own
tables, and every worked example on the page is run through the real
`latex-squiggly` binary by `scripts/make-site.py`, so the page cannot claim a
conversion the app does not make. See [site/README.md](../site/README.md).

## Repository layout

```
.github/            issue and pull request templates, CI and site deployment
Sources/            the Swift package: engine, typing rules, suppression rules,
                    the macOS app, the command-line tools and the test suite
Tests/              the swift test wrapper around the suite
Package.swift       the Swift package manifest
windows/            the Windows port: engine (Core), tray app (App) and the
                    conformance runner (Conformance), as .NET 8 projects
chrome/             the Chrome extension, with its store listing in STORE.md
conformance/        the reference every port is checked against
assets/             source artwork, and the icons generated from it
scripts/            everything run by hand: build, check, generate, make
site/               the website
docs/               documentation beyond the READMEs
build/              local build output, never committed
```

### Inside the Swift package

```
Sources/LaTeXUnicode/          the engine
  ConversionResult.swift       the result type
  ConversionOptions.swift      the one setting the engine takes
  Tokenizer.swift              string to tokens; longest match, terminator rules
  Converter.swift              public convert(); assembly and strictness
  SymbolEntry.swift            one row of the coverage table, and its lookups
  SymbolTableData.swift        generated
  ScriptTables.swift           generated
  TextOperators.swift          \sin, \log, … as upright roman text
  UnsupportedCommands.swift    recognised but refused, with user-facing reasons
Sources/InputTracking/         when typing becomes a conversion, pure
Sources/AppSuppression/        where to stay quiet, pure
  AppContext.swift             what is frontmost, and which page if a browser
  ExclusionList.swift          the rules, the decision, host matching
  DefaultExclusions.swift      what ships excluded, and what is found on disk
  KnownBrowsers.swift          which apps get asked about their page
Sources/LaTeXSquigglyApp/      the menu bar app
  EventTapController.swift     the tap: buffering, terminators, suppression
  FrontmostAppMonitor.swift    which app is in front, and which page
  BrowserPageReader.swift      the Accessibility reads
  SuppressionGate.swift        cached per keystroke, verified before typing
  ExclusionStore.swift         persistence, defaults, on-disk discovery
  SettingsWindow.swift         the settings window, and what it may ask the app
  GeneralPane.swift            switches, and the permissions stated plainly
  ExclusionsPane.swift         the list editor
  Preferences.swift            every switch's defaults key, in one place
  LoginItem.swift              open at login, and when it cannot be offered

Sources/latex-squiggly/        the command-line converter, for trying things
Sources/latex-squiggly-check/  runs the test suite
```

## Non-goals

No image rendering, cloud sync, accounts, text editor, note-taking, telemetry
or auto-update. The output is always plain Unicode text, and the app never
talks to a network.
